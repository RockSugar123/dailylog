## 1. 需求提出

起点是一个开放问题：**"如果要给这个项目加上一个 RAG 相关的功能，你推荐做些什么？"**

没有从猜测的方案直接动手，而是先摸底代码（数据形态、模型通道、前端结构、打包约束），再用 grill-me 方式逐轮拷问收敛——因为"RAG 功能"可以是搜索、问答、报告增强、知识库等完全不同的东西。

## 2. 需求分析：拷问式澄清（5 轮收敛 + 2 次查证）

每轮只问**当前最影响方案方向**的一个问题，给 2-4 个候选并标注推荐：

| 轮次 | 决策点 | 结论 | 为什么这样问 |
|------|--------|------|--------------|
| 1 | 核心场景 | 历史日志问答（非纯搜索/报告增强/待办关联） | 决定整个功能的形态与价值上限 |
| 2 | 索引范围 | 日报记录 + 报告 | raw 明细与日报内容重复；待办/时长是结构化数据，过滤查询比向量检索准 |
| 3 | 向量化方式 | API embeddings | 本地模型 200-500MB 拖垮 PyInstaller 打包；FTS 中文语义召回差。顺带查证：百炼 text-embedding-v4 有 100 万 Token 免费额度，超出 0.5 元/百万，本项目年成本约 1 元 |
| 4 | 呈现形态 | 用户选"悬浮窗"后**追问一句**：应用内浮层还是系统级窗口？ | 两者架构量级差一个数量级（系统级窗口与托盘生命周期、零窗口循环等已知怪癖纠缠）——确认是应用内浮层，避免方向性返工 |
| 5 | 引用 | 引用 + 可点击跳转 | 问答的价值一半在"找到源头核对"，数据模型（chunk 带日期锚点）必须从一开始就为它设计 |

**停止提问的判据**：剩余未确认点全部只影响细节且有合理默认（SQLite 暴力余弦、按 `##` 小节分块、问答前懒同步、默认百炼、复用总结模型）。这些以"假设清单"形式写入需求确认单，随 PRD 落盘——执行中每条假设都被实现印证或修正。

## 3. 任务拆分

9 项任务按依赖排序，全部纳入 todo 跟踪：

```
通读代码 → config 预设 → llm embeddings 封装 → indexer（分块/索引/懒同步/自检）
→ ask（检索+prompt）→ ui_api 桥接 → 前端浮层 → 前端设置 → 依赖与验证 → STATUS 同步
```

每一步完成即验证（import / 自检 / node --check），不攒到最后。

## 4. 执行中的困难与处理

1. **用户不在场，部分环节做不了**（配 API Key、点 UI 验证）
   处理：先把能做的全部做完并离线验证，需要用户的整理成清单明确跳过；Key 到位后走生产保存路径配置，一次性完成端到端验证。
2. **写完即自查出两处错误**
   自检预期块数算错（5 写成 3、重建后 4 写成 2）、`_now()` 函数重复定义。自检跑出的实际数字反推纠正——"先验证再执行"在小事上也成立。
3. **numpy 未预装**（Python 3.13 环境）
   安装 2.5.2 并写入 requirements.txt；打包侧 PyInstaller 对 numpy 有官方 hook，无需改 spec。
4. **流式输出的桥阻塞风险**
   同步问答会阻塞 pywebview 的 JS 桥（几十秒生成期间窗口控制全部无响应）——STATUS.md 里有手动截屏踩同一坑的案底，直接复用其解法：后台线程 + `evaluate_js` 回推，SSE 逐段解析、80ms 节流；CLI 保留一次性模式。
5. **纯日期提问检索失败**（最有价值的发现）
   "8月28号做了什么？"检索不到当天记录：embedding 对"8月28号"和"2026-08-28"这类日期数字的语义对齐很弱，top-8 全被报告通用小节占据。值得注意的是**生成侧没有跟着幻觉**——反幻觉 prompt 让模型诚实回答"没找到"。修复：`extract_dates` 从问题抽明确日期（含今天/昨天/前天），命中时只在当天块内检索、无匹配回退全局。修复前后同一问题对比：从"没找到"变为准确输出当天工作总结。
6. **密钥安全**
   API Key 在对话中明文出现过一次：Key 只落 `data/.env`（gitignore 内，已验证不会进仓库），并建议用户去控制台轮换。

## 6. 总结：可复用的经验

1. **澄清阶段"能查代码的先查代码"**，问题只留给真正的产品/方向决策；每轮给候选+推荐，降低决策成本。"答错方向代价高"的点（悬浮窗形态）值得多追问一句。
2. **伪向量自检是 LLM 应用的性价比之王**：不调一次 API 就验证分块/同步/删除/重建/检索全链路，后续改动的回归成本近乎为零。
3. **遇到"没反应/答非所问"先分清是检索错还是生成错**：本次日期提问失败是检索问题，但生成侧没幻觉——两层各自治理（日期过滤 vs 反幻觉 prompt），混在一起猜会浪费时间。
4. **项目坑有案底就先查案底**：JS 桥阻塞在 STATUS.md 有现成解法，直接复用比重新设计快且稳。
5. **破坏性边界先确认**：动 git 前先验证 `.env`/索引库确实被忽略，密钥永远不进仓库。

**遗留（按优先级）**：相对时间提问（"上周/上个月做了什么"，需按提问日换算日期范围）；对话历史持久化；打包版部署需重跑 `build.bat`；rerank/混合检索。
