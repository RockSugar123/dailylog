# PRD · 历史日志问答（RAG）

| 项 | 内容 |
|----|------|
| 版本 | v1.0 |
| 日期 | 2026-09-05 |
| 状态 | 待评审 |
| 关联项目 | dailylog · 今日轨迹 |

## 1. 背景与目标

### 背景

dailylog 通过截屏 + 视觉模型持续记录工作时间线（`records/*.md`），并生成日报/周报（`reports/*.md`）。数据按天累积，但查找方式只有两种：按日期翻页、肉眼浏览。当用户"记得做过某件事、但忘了哪天"时，无法用自然语言定位——语义相关但用词不同的内容（如"那个显示问题" vs 记录里的"指示灯黑色字体不可见"）靠关键词搜索也找不到。

### 目标

在应用内提供**历史日志问答**：用自然语言提问（"上个月我在 dailylog 上花了多少精力""哪天修过那个字体 bug"），系统对历史记录/报告做语义检索，由 LLM 组织回答，回答附带**可点击跳转的来源引用**，让答案可核对、源头可回溯。

### 非目标（第一版不做）

- 不把 raw 明细（`records/raw/*.jsonl`）、待办、应用使用时长纳入语义索引（待办/时长是结构化数据，过滤查询比向量检索更准；raw 与日报内容大量重复）
- 不做对话历史持久化（浮层关闭即丢弃）
- 不做系统级全局悬浮窗（只在应用窗口内）
- 不做关键词混合检索、rerank 等检索质量增强
- 不做用量配额控制

## 2. 用户故事

- 作为用户，我想用一句自然语言问"过去一个月我在某项目上做了什么"，直接得到汇总回答，而不用按天翻记录
- 作为用户，我记得做过某件事但忘了哪天，想快速定位到那天的原始记录
- 作为用户，我不信任没有出处的 AI 回答，希望每条回答都能看到它依据了哪些片段、并能一键跳过去核对

## 3. 方案概述

新增 **API 向量化 + SQLite 向量索引 + 应用内对话浮层** 三件套：

- `core/llm.py` 增加 OpenAI 兼容 `/embeddings` 封装，embedding 供应商沿用现有"选预设、贴 Key"的设置模式（默认阿里百炼 `text-embedding-v4`）
- 新增 `core/indexer.py`：把日报/报告按小节分块、向量化，存入 `data/` 下的 SQLite 单文件；问答时懒同步增量索引（不新增定时任务）
- 新增 `core/ask.py`：检索 top-k 片段 → 组装 prompt → 复用现有「报告总结」模型生成回答 + 引用
- 前端在任意页签右下角加悬浮球，点开对话浮层，回答下方展示引用卡片，点击跳转对应日期的记录/报告

## 4. 功能需求

### FR1 内容分块与索引

- 索引范围：`data/records/*.md`（日报时间线）与 `data/reports/*.md`（日报/周报）
- 分块规则：
  - 日报按 `## HH:MM · 分类` 小节切分，每块一个时间段的活动描述
  - 报告按 `##` 小节切分
  - 每块携带元数据：来源类型（record/report）、日期、时间段（日报块有）、小节标题、源文件路径、内容 hash
- 向量与元数据存入 `data/rag_index.db`（SQLite 单文件，位于 `data/` 下，自动被现有备份机制覆盖）
- 截屏"分析失败，下轮自动重试"的占位条目不入索引

### FR2 索引懒同步

- 不新增任务计划；在**每次问答前**触发同步：按文件 mtime + 内容 hash 与索引内记录 diff，增量补齐新增/变更文件的向量
- 源文件被删除（如 `retention_days` 清理）时，对应 chunk 从索引移除
- 切换 embedding 模型或维度时全量重建索引

### FR3 Embedding 服务封装

- `core/llm.py` 增加 `/embeddings` 端点调用（复用现有 `requests.Session`、`trust_env=False` 约定）
- 供应商预设只列**确实提供 embedding 模型**的服务：阿里百炼（`text-embedding-v4`，默认）、硅基流动（`BAAI/bge-m3`）、智谱（`embedding-3`）、OpenAI（`text-embedding-3-small`）等；DeepSeek/Kimi 无公开 embeddings 端点，不列入
- 遵守模型限制：单请求批次 ≤10 条文本、单条 ≤8192 Token（分块后远小于此限制）
- API Key 沿用 `.env` 的 `MODEL_KEY_*` 体系与设置页保存流程

### FR4 问答链路

- 浮层提交问题 → 懒同步 → 向量化问题 → SQLite 中余弦检索 top-k（默认 8，常量可调）→ 按相关度排序组装 prompt → 调用现有「报告总结」模型配置的 LLM → 返回回答与引用
- **日期感知检索**：问题含明确日期（"8月28号"、"2026-08-28"、今天/昨天/前天）时，只在该日期的块内检索，无匹配回退全局——embedding 对日期数字语义对齐弱，须显式过滤；相对时间表达（上周/上个月）v1 不解析
- **流式输出**：回答经 SSE 流式生成，前端逐字渲染；桥接立即返回，后台线程经 evaluate_js 推送增量（80ms 节流），完成后推引用
- prompt 约定：仅基于检索到的片段回答；片段不足以回答时明确说明，不编造；回答中标注所依据片段的编号
- 问答 LLM 复用现有报告总结配置，不新增模型配置项

### FR5 悬浮球与对话浮层

- 应用内右下角悬浮球，**任意页签**可唤出对话浮层（同一 pywebview 窗口内的 HTML 浮层，非新窗口）
- 浮层包含：消息列表（用户/助手消息）、输入框、发送按钮、回答生成中的加载态
- 未配置 embedding Key 时，提交问题给出"去设置页配置"的明确提示（与现有分析/总结未配置时的提示模式一致）
- embedding 或 LLM 调用失败：浮层内显示错误提示，详情落 `dailylog.log`（不吞异常）

### FR6 引用与跳转

- 每条回答下方列出所引用的来源片段卡片：`日期 · 时间段 · 小节标题 · 来源类型`（如"08-28 · 22:44 · 开发 · 日报"）
- 点击引用卡片跳转：日报来源 → 时间线页对应日期；报告来源 → 报告页对应报告
- 引用元数据在建索引时写入 chunk，前端跳转复用现有 `get_records(date)` / `get_report(name)` 链路

### FR7 设置项

- 设置页新增「问答向量化」配置：供应商下拉（预设清单）+ 模型名 + API Key，交互沿用现有模型服务配置
- 默认供应商：阿里百炼 `text-embedding-v4`
- 配置持久化到 `settings.json` / `.env`，与现有体系一致

## 5. 非功能需求

| 项 | 要求 |
|----|------|
| 性能 | 检索为 numpy 余弦暴力计算，1 万 chunk 量级毫秒级；懒同步仅对新增/变更文件调 embedding，单文件秒级；问答端到端时长以 LLM 生成为主 |
| 成本 | `text-embedding-v4` 开通后含 100 万 Token 免费额度（有有效期）；超出后 0.5 元/百万 Token。按当前日报体量，一年数据约 100~300 万 Token，长期成本约 1 元/年 |
| 可靠性 | embedding/检索/LLM 任一环节失败：浮层明确提示 + `dailylog.log` 落 error，不影响截屏/报告等其他链路 |
| 兼容性 | Windows 10/11，Python 3.10+；新增第三方依赖仅 `numpy`；PyInstaller spec 需确认 numpy 正常打包 |
| 隐私 | 日报/报告文本送 embedding API，暴露级别与现有截屏云分析一致，不新增敏感面；`contains_sensitive` 标记仅存在于 raw 明细（不入索引），v1 不做过滤 |

## 6. 数据设计

### 存储文件

```
data/rag_index.db        # SQLite 单文件
```

### 表结构（概要）

```sql
-- 已索引文件登记：懒同步的 diff 依据
CREATE TABLE files (
  path   TEXT PRIMARY KEY,   -- 源文件相对路径
  mtime  REAL,
  hash   TEXT                -- 内容 sha256
);

-- chunk 表
CREATE TABLE chunks (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  file_path TEXT,
  source    TEXT,            -- 'record' | 'report'
  date      TEXT,            -- 'YYYY-MM-DD'
  time      TEXT,            -- 'HH:MM'，日报块有，报告块为空
  heading   TEXT,            -- 小节标题
  text      TEXT,            -- 块正文
  hash      TEXT,            -- 块内容 hash（跳过未变更块的重嵌入）
  embedding BLOB,            -- float32 向量
  dim       INTEGER,
  model     TEXT,            -- 生成向量所用模型，切换模型时全量重建
  embedded_at REAL
);
```

### 桥接 API（ui_api.py）

```
ask(question) -> { answer, citations: [{source, date, time, heading, ...}] }
```

## 7. 验收标准

1. 首次提问自动完成全量建索引，`data/rag_index.db` 生成；此后新增/修改日报或报告，无需重启或定时任务，下次提问即可检索到新内容
2. 语义相关但用词不同的提问能命中（如问"显示问题"能命中"指示灯黑色字体不可见"的记录）
3. 回答下方展示引用卡片，点击可跳转到对应日期的时间线/对应报告
4. 检索不到相关内容时，回答明确说明"记录中没有相关内容"，不编造
5. 未配置 embedding Key 时提交问题，浮层给出"去设置页配置"提示
6. embedding 或 LLM 失败时，浮层显示错误，`dailylog.log` 有对应 error 记录
7. 删除某天记录文件后（retention 清理），下次问答时该文件的 chunk 已从索引移除
8. 设置页可切换 embedding 供应商/模型，切换后索引自动重建
9. `dailylog.log` 无未处理异常堆栈

## 8. 风险与说明

| 风险 | 说明与对策 |
|------|-----------|
| 部分供应商无 embeddings 端点 | 预设清单只列确有的（百炼/硅基流动/智谱/OpenAI），DeepSeek/Kimi 不列入，设置页明示 |
| 切换模型导致向量维度/语义空间不一致 | chunk 记录 `model` 与 `dim`，检测到不匹配即全量重建 |
| 免费额度过期 | 过期后 0.5 元/百万 Token，本项目年成本约 1 元，可忽略 |
| LLM 幻觉 | prompt 限定仅基于片段回答 + 引用卡片可人工核对 |
| numpy 增大安装包 | 约增加十几 MB；替代方案纯 Python 余弦在万级 chunk 下过慢，值得 |
| 数据长期增长 | 一年约 1 万 chunk，暴力检索无压力；数年后如变慢再引入 sqlite-vec（记入待定项） |
| 打包链路 | 索引库在 `data/` 下，build.bat 镜像部署本就排除 `data/`，无新增风险 |
